# Mac 网络诊断：ChatGPT 与 Codex

适合使用 Clash Verge、没有编程基础的 Mac 用户。先诊断，再根据证据决定优化；脚本不会修改 Mac 网络设置。本仓库的开发与模拟检查发生在云端，不是你的 Mac 实测结果。

## 第一次只做这三步

1. 打开 [本仓库](https://github.com/leah122122122/mac-network-config)，点绿色 **Code → Download ZIP**。下载后双击 ZIP 解压。无需安装 Git、Homebrew 或 Python。
2. 按 **Command（⌘）+空格**，输入「终端」或 `Terminal`，按回车。保持 Clash Verge 以你平时的方式运行，先不要改模式或节点。
3. 在终端输入 `/bin/bash `（末尾留一个空格），从解压文件夹把 **diagnose-macos.sh** 拖进终端，再按回车。终端会自动填入文件路径，包括正确处理空格。

等价命令示例（实际路径以拖入结果为准）：

```bash
/bin/bash ~/Downloads/mac-network-config-main/diagnose-macos.sh
```

不要输入 `sudo`，也不要关闭系统安全保护。脚本不需要可执行权限，不需要双击打开 `.sh`。若报「No such file」，重新把解压后的脚本拖进去；若提示仅支持 Mac，说明运行位置不对。

通常需要 3–10 分钟；很多请求超时时可能更久。终端会持续显示进度，**Control+C** 可以中止；中止后的报告不完整，请勿当作最终结论。

## 在哪里找到报告

终端显示中文结果，最后给出完整路径。每次报告独立保存到：

```text
~/Library/Logs/mac-network-config/run-时间-随机字符/报告.txt
```

Finder 菜单「前往 → 前往文件夹」（Shift+Command+G），粘贴 `~/Library/Logs/mac-network-config`，打开最新文件夹中的 `报告.txt`。报告目录仅当前用户可读写；可在 Finder 手动删除该次文件夹，不影响网络。

脚本生成报告和临时文件是唯一的本地写入；临时文件正常退出后删除。它不访问公网 IP 查询服务，但目标服务正常会看到请求的出口 IP。报告不记录出口 IP、不保存响应正文、响应头或原始错误信息。最后显示的本地路径可能包含用户名，DNS 服务器地址也可能标识你的网络，**分享前请删掉或遮住这些信息**。报告不自动上传；不要把报告拖到公开 GitHub Issue 或提交到仓库。

## 具体检查什么

| 项目 | 检查范围与边界 |
| --- | --- |
| 系统 | macOS 版本、进程架构、Apple Silicon / Rosetta 标记；常见位置 Codex.app 的版本和最低系统版本元数据。未找到不等于未安装，ChatGPT 内集成的 Codex 需手动提供应用版本。 |
| 系统代理 | `scutil --proxy` 中 HTTP、HTTPS、SOCKS 启用情况与端口；远程地址隐藏，PAC URL 不输出，也不执行 PAC。仅记录代理环境变量是否存在，不输出值。 |
| DNS | `scutil --dns` 中 DNS 服务器和解析器标记；系统 `dscacheutil` 对六个域名的解析结果数量。隐藏解析地址，识别 198.18/15 Fake-IP；不额外查询外部 DNS。 |
| 本机端口 | 默认探测 7890、7891、7897、1080、10808、10809，加上系统代理中的回环端口。仅连接 `127.0.0.1`，不枚举进程，不确定监听服务身份。 |
| 路径比较 | 不使用显式代理、本机 HTTP、本机 SOCKS5h；每种协议自动选首个能访问 GitHub 的端口。SOCKS5h 把目标域名交给代理解析，实际仍受 Clash DNS 设置影响。 |
| 目标 | `chatgpt.com`、`auth.openai.com`、兼容登录域名 `auth0.openai.com`、`api.openai.com/v1/models`、`github.com`、`api.github.com`，及 Codex 候选路径 `chatgpt.com/backend-api/codex`。这些均为匿名请求，候选根路径可返回 404。 |
| 时序 | 每条选定路径、每个端点做两次独立请求，记录退出码、HTTP 状态、累计 DNS/TCP/TLS/首字节/总耗时与证书校验结果。单次最长 12 秒，不下载正文到磁盘，不跟随重定向。 |

`curl` 不自动采用 macOS 系统代理或 PAC，所以本工具**显式指定路径**，不把 curl 结果当作桌面应用的真实路由。无显式代理的测试仍可能经过 Clash TUN、其他 VPN 或透明网关，**不能保证物理直连**。代理路径的 DNS/TCP 时间常反映本机代理，不能与直连逐阶段直接相减。证书验证保持开启，不使用 `-k`。

这不是速度排名工具，也不是完整应用登录测试。两次短请求不能证明长回复、SSE/WebSocket、HTTP/3、IPv6 或一整天使用稳定。API 端点的状态不等于 ChatGPT 账号或 Codex 订阅状态。

## 怎样看正常和异常

报告分为「已经确认的观测」「可能存在的问题」「还需要进一步验证」。已经确认的是本次采样的事实；原因只有证据充分时才能确认。

| 结果 | 应怎样理解 |
| --- | --- |
| `curl=0`，HTTP 200/3xx | 这次已完成 TLS 并收到响应；3xx 没有被跟随，不能证明重定向后的登录服务正常。 |
| `curl=0`，HTTP 401/403/404/429 | 网络收到响应。匿名 API 的 401 可以预期；403 可能是访问策略、风控或挑战，404 可能仅是根路径不存在，429 可能是限流。都不能单独判定账号失效。 |
| `curl=5/6` | 代理/目标解析失败，需要结合路径判断；不能只凭这一项认定 DNS 污染。 |
| `curl=7` | TCP 连接失败；本机端口可能未监听，也可能远端不可达。 |
| `curl=28` | 请求超时，结合最后完成的连接阶段排查；不能直接认定节点坏了。 |
| `curl=35/60` | TLS 握手/证书相关问题；核对系统时间、证书信任、网络拦截和节点，切勿关闭验证。 |
| `curl=52/56/97` 等 | 空响应、接收或代理握手等失败；保留退出码和路径继续判断，不要直接归因登录问题。 |
| HTTP `000` | 没有取得有效 HTTP 状态，并不是服务器返回了「000 错误」。 |
| `证书校验=0` 但 curl 失败 | 不能证明 TLS 成功；可能根本没到校验阶段，必须一起看 curl 退出码和 TLS 时序。 |
| 常见端口都不通 | 可能 Clash 未运行、端口不同、只监听 IPv6 或模式不同；不等于订阅节点有问题。 |
| 系统解析出现 Fake-IP | 在 Clash Fake-IP 模式下可能正常；不是单独的故障证据。 |

如果 **代理测试较好、无显式代理较差**，优先怀疑应用代理路径不同。如果 **两边都失败**，从 DNS、TLS、超时和服务状态继续缩小范围。如果 **两边都收到响应但 Codex 仍失败**，继续检查登录回跳、账号权限、应用版本、长连接和应用专属域名，不能直接认定「网络已完全排除」。

## 没有找到正确端口时（可选，第一次先不用）

先在 Clash Verge 的设置中查看 HTTP、SOCKS 或 Mixed 端口，不要复制整个配置。若 Mixed 为 7897，可在前面拖入脚本路径之后追加：

```text
--http-port 7897 --socks-port 7897
```

最终类似：

```bash
/bin/bash ~/Downloads/mac-network-config-main/diagnose-macos.sh --http-port 7897 --socks-port 7897
```

只指定你确定的本机端口。指定的路径即使 GitHub 预检失败，也会继续测试全部端点，便于发现「GitHub 被阻断但 OpenAI 可达」。自动模式只测 IPv4、无认证本机代理；IPv6-only、远程/PAC、需认证的代理不在自动验证范围内。错误或未知参数会在联网前停止。`--help` 只显示帮助。

## 第二阶段：把必要信息发给协助者

复制 [REPORT_TEMPLATE.md](REPORT_TEMPLATE.md) 到你的本地笔记填写。先提供：

1. 报告第七节「结论」；如果含 TLS/超时错误，再附第六节对应的失败行。删掉路径中的用户名和不想公开的地址。
2. Codex 的具体报错文字和失败阶段：无法启动 / 登录网页打不开 / 登录后不能回到应用 / 能进入但发任务失败。可以截图，遮住邮箱、头像、工作区名称和账号信息。
3. 应用名称及版本、Clash Verge 版本、当前 Rule/Global/Direct 模式、系统代理与 TUN 是否开启。只说节点地区和编号（例如「日本 A」），不要发订阅、节点地址或密码。

**不要发送** API Key、Cookie、验证码、登录回调 URL（可能含 code/token）、订阅链接、完整 Clash YAML、钥匙串内容或原始应用日志。需要更多信息时，会先限定字段和脱敏方法。

## 第三阶段：有证据后再优化

以下是待验证的方向，不是让你现在逐项操作。任何实际修改前，都应说明风险、明确备份与恢复办法，得到你的确认，然后一次只改变一项并保留前后报告。

| 观察 | 优先考虑的对照 | 风险与恢复 |
| --- | --- | --- |
| 显式代理好，应用差 | 先核对系统代理；必要时短暂 Global 对照以识别规则遗漏；只在应用不遵循系统代理的证据下考虑 TUN。 | Global/TUN 会影响其他应用和流量；TUN 还可能影响局域网与其他 VPN。记录原模式、系统代理/TUN 开关；失败时逐项恢复，必要时退出 Clash 并通过系统设置核对代理。 |
| 全局好，Rule 差 | 在现有配置的本地副本/覆写中补充规则，把相关域名送到同一个稳定策略组，核对规则顺序和 REJECT/DIRECT 命中。 | 错误顺序或订阅更新会覆盖规则。保留原配置，撤销本次覆写并切回原配置恢复；不要直接改订阅源文件。 |
| DNS 失败或 Fake-IP 路径异常 | 先核对 Clash DNS 是否实际接管，观察系统解析与 SOCKS5h 的差别，再考虑 DNS 模式/上游的单项对照。 | DNS 改动可能影响所有站点；先记下原服务器、模式和选项，恢复原设置并重启应用验证。不要未经验证就替换成固定公共 DNS，也不自动清缓存。 |
| 代理也有超时/抖动 | 固定地区和节点，以同一配置在不同时段重复脚本，结合 10–15 分钟真实长回复、重新连接和登录验证。 | 切节点会改变出口 IP，可能触发额外验证；减少频繁切换，随时切回原节点。优先成功率、低超时、低抖动、稳定出口和长连接支持，而非单次最低延迟。 |
| 网络样本正常但应用失败 | 核对官方当前系统要求、应用版本与登录阶段，查看服务状态；需要时再做账号/软件排查。 | 不应先重置网络、重装、删除登录数据或关闭 TLS 验证；这些操作会引入新变量或丢失信息。 |

规则讨论的起点是 `chatgpt.com`、`openai.com`（含登录/API 子域名）及实际请求涉及的 `oaistatic.com`、`oaiusercontent.com`、`auth0.openai.com`。GitHub 网页/API、内容域名是否加入同一策略组，应依具体仓库任务与命中记录判断。这里不是完整域名白名单，不提供可直接覆盖现有配置的 YAML；应参考 [OpenAI 官方网络建议](https://help.openai.com/en/articles/9247338-network-recommendations-for-chatgpt-errors-on-web-and-apps) 并核对当前版本。TLS 拦截、WebSocket 升级或长连接超时也可能影响 Codex，短 HTTPS 探测无法排除它们。

修改前的备份仅保存在你 Mac 上：截图模式和各开关；使用 Clash Verge 当前版本提供的导出/备份功能保存原配置（若有），或在 Finder 复制待修改文件。**备份可能含订阅凭据，勿上传或发给协助者。** 对手动系统 DNS 更改，先记录原来是自动还是手动、原服务器和顺序。恢复时切回原 Clash 配置及模式、撤销本次规则/DNS覆写，按原记录恢复系统代理、DNS 和 TUN，再重跑诊断。未经你的确认不执行这些操作。

参考：[OpenAI 服务状态](https://status.openai.com/)、[Codex 官方文档](https://developers.openai.com/codex/)、[ChatGPT macOS 系统要求](https://help.openai.com/en/articles/9395554-what-are-the-system-requirements-for-the-chatgpt-macos-app)。请按你实际使用的是独立 Codex 还是 ChatGPT 中的 Codex，核对对应发行版；不要套用另一个应用的要求。

## 安全边界与验证情况

- 不使用 sudo，不修改代理、DNS、路由、证书、防火墙、Clash 配置，不安装软件，不访问 Clash 控制 API。
- 不读取浏览器或应用登录文件、环境变量中的密钥值、VPN 订阅、节点密码、API Key 或 Cookie。curl 忽略 `.curlrc` 与代理环境变量，不携带账号；不使用 curl 的 verbose/trace。
- 所有探测目标固定，本机端口参数只能是数字；不会接受远程代理 URL、回调 URL 或认证信息。
- 默认报告位于仓库之外；`.gitignore` 也排除了常见报告路径，但它不能防止你手动上传或强制提交。
- 在 Linux 开发环境检查 Bash 语法、非 macOS 保护，并用隔离模拟命令验证主要故障分支；没有把云端请求当成 Mac 网络实测，也没有真实 macOS 环境完成端到端验证。请以你的 Mac 本机报告为准。
