## 自动化验证

开发者运行：

```bash
python3 tests/test_diagnostics.py
```

普通用户不需要 Python，也不需要运行测试。

测试在临时目录中复制待测脚本，仅对这份副本替换 macOS 系统命令路径为模拟命令，使用真实 Bash/awk/OpenSSL 校验握手键。模拟 resolver 的 watchdog 缩短为 1 秒，另有独立超时测试。生产文件没有测试开关或跳过平台限制的环境参数，测试不访问公网。

覆盖内容：

- Bash 语法、非 Mac 拒绝执行、帮助、未知参数、非法/缺失端口；启动脚本处理空格和中文路径。
- 默认三轮与 quick 两轮采样、报告/样本行数和字段结构。
- 13 类端到端模拟：正常响应、没有本机代理、无显式代理超时、TLS 失败、系统 DNS 无结果、终端/launchd 冲突与旧端口、有效 101、无效 Accept、GitHub 预检失败但保留对照、仅 IPv6 回环监听、IPv6 连接差异、最低系统版本不匹配、间歇性失败。
- CONNECT 200 不等于源站成功；响应头白名单过滤、错误/缺失指标、无效握手头部、认证拒绝与真实有效 101 的区别。
- 有效 101 后 curl 达到等待上限 28 仍仅记为已验证握手，不虚构长连接故障或稳定性。
- 解析器超时终止；用户配置文件内容保持原样；本机报告和目录无组/其他用户权限。
- 模拟订阅链接、代理密码、API Key、Cookie、远程地址和自定义 CA 路径不出现在终端输出与报告中。launchctl 模拟器拒绝任何 getenv 之外的调用，curl 模拟器要求固定目标、清除继承路由/CA、TLS 校验开启且不携带认证。

## 人工代码审查（同一开发者完成，非独立审计）

检查了入口、环境分类器、响应解析器、结论生成器与文档的一致性，并修正以下风险：

1. 系统代理原始输出可能含 PAC URL。改为先经过白名单再写临时文件，只保留回环代理、数字端口与启用状态；不保存原始 URL。
2. HTTP CONNECT 200、源站 101 与 TLS/Accept 校验需要区分。解析器按最后一个 HTTP 响应重置握手标记；只有完整条件满足才输出 valid101。
3. GitHub 单目标预检失败不能直接放弃所有代理测试。保留开放/指定端口但标明协议未验证，避免把 GitHub 策略误归因 OpenAI。
4. 地址族测试在代理下只覆盖到代理的那一段；报告明确边界，不据此关闭 IPv6。
5. 用户 launchd 与终端不是已运行应用的环境快照；只提示潜在冲突，不触发 setenv 或清理。
6. 不读取 config.toml 正文、`.env`、认证、日志或完整进程环境，不执行 app 内二进制；不 source/eval 用户配置。
7. 报告位于仓库之外；额外忽略观测样本、备份与环境文件。临时文件退出删除，超时保护只终止本次 resolver 子进程。

没有发现已知阻断交付的问题，但这不是安全保证。仍需真实 Mac 本机验证 Apple Bash 3.2、系统工具行为、应用版本、下载/启动体验和实际故障。只使用 Bash 3.2 语法并不能替代在该解释器上实测。
