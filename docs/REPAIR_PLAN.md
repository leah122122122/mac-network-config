# 后续修复与恢复方案（当前不执行）

本文件是计划，不是运行指令。没有修复程序被诊断入口调用。用户明确要求：先交付诊断，等待 Mac 本机结果，再决定实施修复。

## 当前优先级

1. 对 7897 的失败做多轮复核：若匿名 HTTPS 本身仍反复超时，优先排查代理链路/节点/上游，不先注入新的全局环境变量。
2. 若 curl 的显式代理稳定、应用仍失败，核对实际应用版本、启动方式、指定环境变量差异及可能受影响的通道。
3. WebSocket 401/403 或没有 valid101 不能单独触发修复。必须结合实际应用表现或进一步限定的脱敏证据。
4. 若客户端版本与公开故障接近，核对官方发布说明与支持渠道；不自动降级、重装、删除状态或退出账号。

## 候选变更必须逐项审批

| 候选 | 适用证据 | 风险 | 备份与恢复要求 |
| --- | --- | --- | --- |
| 单次节点/规则对照 | 同一代理端口 HTTPS 多次失败；特定模式差异有证据 | 出口变动可能触发验证；影响其他流量 | 记录节点匿名编号、原模式、系统代理/TUN 开关；Clash 本地导出/复制原配置，保留敏感备份于 Mac。失败后切回原配置和节点，再重测。 |
| 修正过期代理变量 | 具名变量指向不可连接旧端口且已核对来源 | 影响使用该变量的应用；已运行进程不更新 | 精确备份每项“是否存在”和原值，禁止 source/eval 还原脚本；原值可能含认证，不能放报告/仓库。恢复时逐项恢复存在状态和值；不把一律 unset 当作恢复。 |
| 应用进程单次代理对照 | 官方/源码支持已核对、代理路径稳定、明确需要排查环境继承 | 可能启动新实例或与现有实例冲突；不能保证所有组件继承 | 先保存工作并由用户退出应用；隔离到单次子进程，不改 shell/launchd。记录启动前状态；结束对照后用原启动方式恢复。具体命令需按版本验证后另行开发。 |
| `respect_system_proxy` | 本机具体构建确认包含该功能，明确有效配置层且系统代理正确 | 上游仍标开发中，可能不覆盖所有组件；配置可能有其他覆盖 | 经同意后在本机备份原文件、权限和校验值；只改指定表/键，做语法检查、差异预览与提交前确认。恢复须校验文件是否又被他人/应用更改，冲突则停止而非覆盖。未核对版本不制作默认开启程序。 |
| DNS/证书/IPv6 | 有具体解析/信任链/地址族证据，排除代理测试限制 | 影响整个系统、局域网或安全信任 | 先记录自动/手动配置及全部原值；提供明确逐项恢复方法，得到确认才动。当前无此授权，不做自动修改。 |

用户的 Clash/Codex 备份可能包含订阅、密钥或访问令牌。诊断工具不会读取或复制它们；若将来需要配置修复，须先单独解释备份的敏感性和仅本地保存方式，获得授权。不要为方便把备份上传 GitHub。

## 独立修复程序的交付门槛

只有确定一个受支持、能安全自动化的具体措施后才开发。最低要求：默认只预览 → 展示逐项变更及风险 → 本地备份和完整性校验 → 明确确认 → 原子修改与验证 → 提供独立恢复入口。恢复应保留后续编辑，版本/路径/原文件不符时拒绝覆盖；不读取或输出无关凭据。

不允许默认全局 `launchctl setenv`、替换 provider、强制 HTTP 回退、禁用 TLS 校验、修改 app 包、修改订阅、删除登录数据或自动执行网上修复命令。当前 README 的一条命令只会诊断。
